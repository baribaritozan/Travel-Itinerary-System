## 状態とイベントの設計

| 状態 | 保持・更新する場面 | 混同しないもの |
| --- | --- | --- |
| selectedDay / filters / mapTimeRange | 従来のルールを維持 | メニュー開閉、全画面表示 |
| focusedItemId | 本文/ノード/地図、縦スクロール停止後。非表示候補の子は切替時に解決 | 比較対象、詳細、全画面表示 |
| expandedItemIds | 個別の詳細開閉、すべて閉じる | 案の全画面表示、候補の表示 |
| selectedIds / 親の三状態 | 比較対象の明示操作、全解除、再取得後のID整理 | 比較モードの終了、候補切替 |
| activeCandidateByGroup | 実スクロール位置、前後、keyboard、PCでの明示操作 | 採用・確定・永続保存 |
| comparisonMode | 比較操作の可視/不可視 | 選択集合の削除 |
| 全画面対象ID / 復帰アンカー | 案名で開く、戻る、対象削除/非表示の解決 | 個別詳細、フォーカス、地図拡大 |
| mapPanelMode / 補助メニュー | 地図のサイズ、補助操作の開閉 | 日付・フィルター・旅程データの初期化 |

全画面表示から戻る時は、親画面の公開IDと表示位置を使って復帰する。全画面表示中に変更したアクティブ候補・詳細・選択等は最新版を維持し、入る前のsnapshotで上書きしない。再取得時にはIDの存在、選択日、フィルターを評価して無効な全画面対象を解除する。

横スワイプ/前後操作/案名タップと、縦スクロールによる自動フォーカスを分ける。DOM置換や復帰時のプログラムスクロールが、利用者の操作で選んだ候補・子のフォーカスを勝手に置き換えない。背景を隠すだけでなく、非表示の操作へTab移動できないようにする。

## タイムラインの設計と測定

- 画面左の時刻列・ノード列・本文開始位置を共通トークンにし、親子の深さでは変更しない。320pxでは必要に応じて余白を調整するが、本文・時刻を読めないほど縮めない。
- ノードの縦位置は対応する見出し/予定名の中心。接続線はカードの隙間をまたぐ。本文の高さや時刻差を固定値で仮定しない。
- 高さの変化に追従する方法はCSSを優先する。計測が必要なら変更をまとめ、ResizeObserver等で更新する。地図のパンや選択更新を計測処理の副作用にしない。
- ノードの見た目と操作域を分けて44pxを確保し、近接ノード同士や本文ボタンと重なる場合は行間も確保する。
- 検証では可視ノードと対応タイトルの中心座標差、カード間の共通軸の差を実測し2px以内を確認する。200%文字、詳細展開、3候補、幅変更、全画面で再測定する。
- 自由時間内候補と時刻未定寄り道を、通常旅程の時間軸へ自動配置しない。PCの並列案はそれぞれの列で整列し、代替案同士を一本の時系列として接続しない。
